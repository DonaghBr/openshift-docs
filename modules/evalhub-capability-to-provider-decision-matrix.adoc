== Using the decision matrix

When your AI coding agent recommends an evaluation framework, it uses the mappings in this matrix as guidance.
For lm-evaluation-harness, the agent reads the `evaluates`, `recommended_when`, and `target_type` fields from provider metadata, which encode these mappings.
For other providers, the agent relies on static skill descriptions rather than API metadata.

[NOTE]
====
Entries marked "(planned)" indicate providers that are not yet included in the default {evalhub} installation.
The recommendations shown for these providers represent the expected workflow when they become available.
====

If you need to evaluate multiple capabilities, select providers for each capability.
The `complements` field in provider metadata indicates which providers work well together.
For example, after running lm-evaluation-harness for reasoning benchmarks, the agent might suggest Garak for safety evaluation and GuideLLM for performance benchmarking.

== Multi-provider evaluation strategy

For comprehensive model evaluation, consider combining providers across multiple dimensions:

Quality evaluation:: Use lm-evaluation-harness for reasoning and knowledge. When RAGAS becomes available, use it for RAG-specific quality.
Safety evaluation:: Use Garak for toxicity and adversarial robustness.
Performance evaluation:: Use GuideLLM for latency and throughput under production-like conditions.

You can group these into an {evalhub} evaluation collection that runs all benchmarks in a single operation, with weights and thresholds that reflect your quality priorities.
